# 沉浸模式 · 同步门盘

2026-11-05。局部 skin：保留五目的地、单击直选和既有三维换景，替换横条外观并修复浮层避让。

## 体验与参考分析

核心承诺：像拨动实体门锁一样选择门的另一端；城堡和景观始终是主体。旅程：看左下圆盘 → 点击带文字的四色扇区/中心工坊 → 两处指针同步转动 → 环境到达、状态文字确认。普通模式和沉浸模式共用一套按钮，不增加弹出菜单。

参考1（用户重叠截图）：长条与居中操作浮层各自定位，造成横向碰撞；取消目的地横向展开，给圆盘和操作入口明确保留区域。
参考2（用户门锁近景）：借用青铜双圈、细刻度、四色搪瓷、双头指针；色序严格对应实体门：左上花田、右上港口、左下王都、右下星夜。
参考3（现有 quiet-immersion 与实体 MagicDoor）：保持暗绿半透明工具、原场景揭景与自由相机，不引入其他视觉风格。本次为本地局部修复，使用用户参考和项目实物，不扩展外部趋势研究。

层级：城堡 → 圆盘/场景状态 → 展开后的操作。圆盘约144px，文字按钮覆盖四象限，中心44px按钮回工坊；独立“查看门锁”文字按钮保留原聚焦功能。颜色之外提供文字、aria-pressed、焦点描边。

## 动作与空间

不是新增3D：实体门保留Three.js真实几何；屏幕控件用SVG+原生HTML按钮，准确表现同一个平面圆盘，避免额外模型和渲染开销。

| 状态 | 指针 / 交互 | 布局 |
|---|---|---|
| 初始/返回工坊 | 指针向上，中心选中 | 左下固定尺寸 |
| 选目的地 | 按钮立即选中；UI每次环境发布读取实体needleAngle，取反用于屏幕坐标 | 无宽度变化 |
| 0–40% | 与门上机构同一smoothstep角度、最短转向，无独立CSS延时 | 状态文字“前往…” |
| 40–100% | 指针停稳，保留原2.6s环境揭景 | 圆盘不移动 |
| 快速/反向再选 | 沿用Scene完成上一目的地再出发的规则，两指针同步 | 同上 |
| 减少动态 | 两指针立即落位；原场景减少动态规则 | 无多余动画 |
| 沉浸工具展开/收起 | 保留现有透明度/位移动作，隐藏后inert | 桌面操作栏在圆盘右侧与展开入口左侧；窄屏在圆盘上方；短横屏用紧凑双行 |

键盘保留1–5直选，Tab+Enter/Space访问全部目的地；圆盘组提供方向键/Home/End。Escape仍退出沉浸。控件焦点不触发场景手势。

## 实现与约束

- 共享门盘角度/扇区定义（AC-P2）；Scene向UI发布实际角度，避免两处插值漂移。
- Portal只替换同一nav中的控件；删除横条/滑块布局（AC-P1/P3）。
- CSS明确底部安全区：桌面水平分区，≤900px竖向避让，safe-area、375px、768px、短横屏（AC-P1/P4）。
- 不修改城堡/景观几何、相机、换景shader、行走/拆解/导览逻辑；不新增依赖或网络资产。
- 加载仍禁用按钮，错误由现有重试层接管；144px小型SVG与按需环境发布同步，不另建动画循环。

设计门：体验/参考一致，五态、双向、中断、减少动态和空间避让已定义；HTML按钮+SVG符合平面控件，实体三维保持原链路。按直接请求继续实现，验证见 ../acceptance/howl-castle-portal-dial.md。
