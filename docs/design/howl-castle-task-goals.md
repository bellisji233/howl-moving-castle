# 哈尔的移动城堡 · 交互式 3D 拆解体验任务目标

日期：2026-11-03

本文定义项目目标、阶段范围和验收标准。后续已获得从 P0/P1 开始实施的用户授权；具体实施状态以检查记录为准，不把目标文档作为开发完成报告。

## 1. 总目标

制作一个以《哈尔的移动城堡》前期巨型步行形态为目标、以用户提供的四张图为美术与结构参考的真实 Web 3D 体验：用户能围绕城堡观察，看它以四条机械鸟腿行走，选中并拆开建筑、外壳与机构，理解各部分之间的运动关系。

最终体验应同时成立：外形可辨识、运动有重量、拆解有结构、操作可恢复。程序化代理是开发阶段的产物，不能仅因功能跑通就替代最终视觉目标。

工作分类：结构重建。核心交互是围绕三维实体探索，界面围绕场景组织。

## 2. 面向谁、带来什么体验

- 面向喜欢动画美术、机械结构和互动模型的普通观众，优先支持桌面浏览，兼顾手机触控。
- 核心感受：这是一座沉重、古怪、有生活气息的移动建筑，可以靠近研究和亲手拆开。
- 主要旅程：看见完整城堡 → 绕行观察 → 播放与调整步态 → 选择部件 → 拆解或透视 → 隔离研究 → 返回完整城堡。
- 注意顺序：先整体轮廓，再运动中的部件，最后阅读少量说明；宽屏主场景约占可用画面 70%。

## 3. 五项成品目标

### G1 · 外形与材质

保留头重脚轻的整体比例、机械脸与嘴部入口、非对称堆叠房屋、塔楼、长短歪斜的烟囱、外露管线和四条鸟腿。五个观察方向均有完整结构，避免只有正面成立。

美术方向：浅沙色工作室、低饱和灰铁与铜锈、旧黄铜、赭红屋顶、暖色窗光；通过板缝、铆钉、屋瓦、材质粗糙度与接触阴影建立尺度，避免均匀光滑的玩具质感。相似度与最终质感保留用户审美验收。

### G2 · 步态与重量

四足异相迈步，以足端轨迹和双骨 IK 驱动关节；支撑足在世界坐标下锁定。主体有受控的起伏与摇摆，建筑、烟囱有小幅滞后动作。暂停、慢速、变速后保持时间连续，运动和读数共用同一状态。

步态参数是设计假设；不声称还原电影原始绑定或真实物理动力学。

### G3 · 可逆的拆解

实体网格支持点选、高亮和名称说明；提供连续爆炸滑块、外壳透明、部件隔离及复原。至少覆盖主体、脸部、建筑、塔楼、烟囱、管线、四个独立腿组、推演传动和魔法核心。

每个可选部件具有稳定 ID、层级、初始变换和拆解偏移。完整 ↔ 拆解、实体 ↔ 透明、整体 ↔ 隔离均可双向操作，并可与播放/暂停组合。

### G4 · 易懂的操作与导览

支持绕行、缩放、五个镜头预设、播放暂停、速度调整和一键回到初始状态。面板展示实际步态相位、四足接地状态、计算关节角度与速度控制量。

自动导览依次展示整体、步态、脸部、拆解和内部。用户操作立即接管，保留当前镜头连续性；闲置恢复时间在开发前确定并记录。减少动态效果时关闭自动环绕及装饰晃动，保留主动操作。

### G5 · 可运行、可维护、可验证

交付可本地启动和构建的项目、源码、使用说明、资产来源记录、五视角截图、步态检查帧序列、交互及性能检查报告。手机保留旋转、选择、播放暂停和拆解等核心操作。

## 6. 媒介与实现方向

采用真实几何与相机空间：Three.js + TypeScript + Vite。三维场景负责模型、光影、选择和拆解；HTML 界面负责文字、控制与状态。场景、资产、运动求解、拆解、导览和界面分层，参考 teardown 的统一状态与检查方法。

程序化几何用于结构验证和可维护部件；细节复杂处根据资产审计结果采用专门建模或可用的授权网格。需要时引入 Blender。不得用图片拼贴、CSS 透视或只有一面成立的模型替代完整三维体验。

模型来源可替换，部件 ID 与交互语义保持稳定。多文件构建优先，不把单 HTML 或视频作为首版硬要求。

## 7. 范围边界与当前依据

- 当前工作区仅观察到 teardown 示例输出，尚无本项目应用源码；尚未完成全机资产搜索。
- 已收到任务书 HTML 和四张参考图；其中提到的 `parts.json`、`references.json`、`CODEX_START.md` 未随本次附件提供，可在 P0 依据一致结构重新建立。
- 不纳入首版：电影剧情重演、角色、原片音乐、完整室内漫游、独立魔法门机构专题、视频成片、在线公开发布。
- 内部传动、魔法动力和接触求解均清楚区分视觉事实与作者设计；不制造扭矩、压力等无依据的工程实测值。
- 若外形或材质不达目标，继续修正资产与建模路线，报告具体差距；不得将代理模型重新命名为高保真成品。
- 本轮不请求素材或访问权限。进入开发后，只有确实影响目标且无法合理替代的资源缺口才构成阻塞。
