# P0 / P1 实施与检查记录

日期：2026-11-03。入口：`http://127.0.0.1:5186/`。源码位于 `howl-castle-app/`，证据位于该目录的 `artifacts/p1/`。

## 当前交付与边界

已建立资产审计、统一坐标和分件表、视觉/空间/运动方案，并实现真实三维结构研究场景。使用 Three.js + TypeScript + Vite，几何与材质在本地生成，HTML 提供观察工具和说明。

造型为程序化研究版本，包含多层机械圆顶、炮眼、下颌入口、半木构房屋、塔楼、歪烟囱、管线、鳍板、侧齿轮及四个鸟足组。浅纸色场景、旧铁/黄铜/赭红屋顶与暖窗为材质方向。此次未导入第三方城堡模型。

轮廓和材质仍需审美验收，不能将本阶段称为高保真成品。与参考相比，外壳的有机不规则程度、入口比例、建筑密度和材质老化仍有精修空间。

## 性能与验证限制

- 最终构建约 728KB 未压缩；主要 JS gzip 约 166KB。没有网络媒体和大型模型下载。该数据说明资源体量，不说明设备帧率。
- 静态观察使用按需渲染；重复细节在部件内按材质合并。当前满足预设的 <250k 三角面、<250 次绘制调用预算。
- 镜头正反向的起止状态及中途接管已操作；截图采集时间存在工具延迟，没有得到均匀 200ms 的完整连续性证据。相关记录为 partial，不能据此宣布运动验收通过。
- 独立无头 Chromium 检查路径不能建立 WebGL 上下文；随后使用 Codex 内置浏览器完成实际渲染与操作。没有据此宣称 Chromium 兼容性或目标集显帧率通过。
- 手机结果是浏览器视口模拟与指针操作，尚非移动设备上的真机手势与性能验收。
- 减少动态效果分支已实现但未模拟系统设置完成实测；完整对比度扫描、WebGL/加载失败注入与冷启动性能均保留待测。

## 已修正的实际问题

1. 首轮模型碰到页头和底部工具条：调整镜头距离与取景，重新采集五视图。
2. 小铆钉面数过多：减少小球细分，总面数从约 38.8 万下降；增加第二层圆顶后最终为约 24.7 万。
3. 对照图中圆顶层次不足：扩大后圆顶，补充金属鼓身及炮眼；侧圆顶向后嵌入主体。
4. 手机部分触控目标不足 44px、选件说明和缩放条重叠：修正最小宽度、取消缩放条缩小变换，并调整位置；390px/375px 重新检查。
5. 镜头按钮选择器误包含 canvas 的诊断属性：限定到 button，避免点击模型触发镜头重置。
6. 选择高亮原先会清掉暖窗原有发光：保存并恢复每个网格的基础材质状态。
7. 键盘/缩放中断镜头后状态标记不一致：统一清除镜头过渡状态，重新操作确认。
